# Backend. Задание 3. SQLAlchemy и Alembic

Учебный проект базы данных барбершопа «БРИТВА». В проекте используются SQLAlchemy 2.x, SQLite и Alembic.

## Состав проекта

- `solution.py` — ORM-модели, связи, заполнение демонстрационными данными, запросы, проверка свободных интервалов и создание записей.
- `alembic.ini` — конфигурация Alembic.
- `migrations/env.py` — подключение Alembic к метаданным моделей и базе данных.
- `migrations/versions/0001_initial.py` — начальная миграция.
- `tests/` — автоматические проверки моделей, связей, запросов, бизнес-логики и миграций.
- `requirements.txt` — зависимости проекта.

## Структура базы данных

В базе используются пять таблиц.

1. `categories` — категории услуг.
2. `services` — услуги, связанные с категориями.
3. `masters` — мастера.
4. `master_services` — промежуточная таблица связи мастеров и услуг.
5. `appointments` — записи клиентов к мастерам на услуги.

Связи:

- Категория и услуги: один ко многим.
- Мастера и услуги: многие ко многим.
- Мастер и записи: один ко многим.
- Услуга и записи: один ко многим.

В моделях применяются ограничения целостности: внешние ключи, проверки цены и продолжительности, проверка времени окончания записи и допустимых статусов.

## Установка

Рекомендуется Python 3.10 или новее.

```powershell
cd backend-3-practice
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Первый запуск через Alembic

Для новой базы данных выполни команды в указанном порядке:

```powershell
alembic upgrade head
python solution.py seed
python solution.py queries
```

Alembic создаёт структуру таблиц. Команда `seed` добавляет демонстрационные данные. Повторный запуск `seed` не дублирует данные.

Не запускай `python solution.py init-db` перед `alembic upgrade head` на одной и той же новой базе. `init-db` предназначена только для отдельного демонстрационного запуска без миграций.

## Проверка свободного времени

Без указания услуги длительность проверяемого интервала равна шагу:

```powershell
python solution.py slots --master-id 1 --date 2030-01-15 --step-minutes 30
```

Чтобы проверять интервалы с учётом длительности конкретной услуги, передай `service_id`:

```powershell
python solution.py slots --master-id 1 --service-id 1 --date 2030-01-15 --step-minutes 30
```

Функция `free_slots` проверяет существование мастера и услуги, соответствие услуги специализации мастера, рабочее время с 09:00 до 21:00, продолжительность услуги, пересечение с существующими записями и прошедшие интервалы.

## Основные ORM-запросы

В `solution.py` реализованы функции:

- `get_services_with_categories` — получение услуг вместе с категориями через JOIN.
- `get_services_by_max_price` — фильтрация услуг по цене.
- `get_masters_for_service` — поиск мастеров, оказывающих выбранную услугу.
- `get_appointments_for_master` — получение записей мастера с сортировкой по времени.
- `get_appointment_counts_by_master` — подсчёт записей с GROUP BY и COUNT.
- `get_completed_revenue_by_category` — расчёт суммы завершённых записей по категориям с GROUP BY и SUM.
- `free_slots` — вычисление доступных временных интервалов.
- `create_appointment` — проверка и создание записи.
- `cancel_appointment` — отмена записи без физического удаления.

## Миграции Alembic

Применить все миграции:

```powershell
alembic upgrade head
```

Посмотреть текущую ревизию:

```powershell
alembic current
```

Посмотреть историю миграций:

```powershell
alembic history
```

Откатить последнюю миграцию:

```powershell
alembic downgrade -1
```

Откатить все миграции:

```powershell
alembic downgrade base
```

После отката снова применить миграции:

```powershell
alembic upgrade head
```

Создать новую миграцию после изменения моделей:

```powershell
alembic revision --autogenerate -m "описание изменений"
```

Автоматически созданную миграцию необходимо просмотреть перед применением.

## Путь к базе данных

По умолчанию используется файл `salon.db` в каталоге `backend-3-practice`.

Чтобы указать другую базу, можно задать переменную окружения `DATABASE_URL`.

Пример для PowerShell:

```powershell
$env:DATABASE_URL = "sqlite:///C:/AI/Project/salon.db"
alembic upgrade head
```

Для SQLite включена проверка внешних ключей через `PRAGMA foreign_keys=ON` для каждого подключения, в том числе при работе миграций.

## Запуск тестов

```powershell
pytest -q
```

Тесты проверяют создание таблиц миграцией на чистой базе, повторное применение после отката, внешние ключи, связи, заполнение данных, ORM-запросы, проверку свободных интервалов, конфликты записей и отмену записи.

## Важные особенности

- Записи и справочники хранятся в SQLite.
- Статусы записей: `booked`, `completed`, `cancelled`.
- Отмена меняет статус записи на `cancelled`; запись остаётся в истории.
- При проверке свободных интервалов отменённые записи не блокируют время.
- Время в SQLite хранится как локальное время без информации о часовом поясе. Перед сохранением timezone-aware значения преобразуются в локальное время машины.
- Демонстрационные записи используют дату 15 января 2030 года, чтобы тестовые примеры не устаревали.
