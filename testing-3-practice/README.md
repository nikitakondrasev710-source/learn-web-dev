## BUG-001. При листании месяца назад выбранным остаётся прошедший день

| Поле | Значение |
|---|---|
| **Приоритет** | Major |
| **Серьёзность** | Средняя |
| **Окружение** | Chrome 157, Windows 11, http://localhost:3102 |
| **Компонент** | Календарь (React-версия) |
| **Предусловие** | «Сегодня» = 19.11.2026, выбран день 25 |

**Шаги воспроизведения**
1. Открыть страницу «Выбор даты и времени».
2. Нажать стрелку «‹» — перейти в октябрь 2026.
3. Посмотреть, какой день выделен.

**Ожидаемый результат:** выбранным становится первый доступный день
месяца (1 ноября), либо день, который не в прошлом.

**Фактический результат:** выбранным остаётся число 25, хотя весь
октябрь уже прошёл. В нижней панели отображается «25 октября» —
дата, на которую записаться невозможно.

**Причина:** при смене месяца состояние `selectedDay` не проверялось
на доступность в новом месяце.

**Исправление:** добавлена функция `normalizeSelectedDay()`, которая
при листании подбирает первый доступный день месяца
(`tests` — ручная проверка TC-08).

**Статус:** Исправлен, проверен.

**Шаги воспроизведения**

**Ожидаемый результат:** слоты отображаются только для последнего

## BUG-007. Ошибка сборки Vite: посторонний PostCSS-конфиг

| Поле | Значение |
|---|---|
| **Приоритет** | Blocker |
| **Серьёзность** | Высокая |
| **Окружение** | frontend-3-practice, Vite 8 |

**Шаги воспроизведения**
1. `npm run dev` в `frontend-3-practice`.
2. Открыть http://localhost:3001.

**Ожидаемый результат:** приложение открывается, CSS загружается.

**Фактический результат:** `500 Internal Server Error`,
в консоли `Invalid PostCSS Plugin found at: plugins[0]`,
белый экран.

**Причина:** Vite находил `postcss.config.mjs` в родительской папке
`Downloads`, который ссылался на отсутствующий `@tailwindcss/postcss`.

**Исправление (финальное):** в `vite.config.js` обоих проектов
явно отключён поиск PostCSS-конфига в родительских папках:

```js
css: {
  postcss: { plugins: [] },
}
```

Так сборка не зависит от того, что лежит рядом с репозиторием.
Ранее предлагался обход — запускать проект из чистой директории;
он не годится, потому что не воспроизводится у другого разработчика.

**Проверено:** `npm run build` в `frontend-3-practice` и
`frontend-4-practice` — `✓ built in ~150 ms`, ошибок нет.

**Статус:** Исправлен в конфиге, проверен сборкой.

## BUG-009. Кнопка «Далее» не реагирует на нажатие — шаг «Подтверждение» недостижим

| Поле | Значение |
|---|---|
| **Приоритет** | Major |
| **Серьёзность** | Высокая (сквозной сценарий не проходим) |
| **Окружение** | Chrome 157, Windows 11, `frontend-4-practice`, http://localhost:3000 |
| **Компонент** | Панель итога, `src/components/SummaryBar.jsx` |
| **Требование** | REQ-44, REQ-72 |
| **Найдено** | Исследовательская сессия, 22.11.2026, 14:21 |

**Предусловие:** «сегодня» сервера — 17.10.2026, выбран день 17, выбран слот 10:00.

**Шаги воспроизведения**
1. Открыть http://localhost:3000.
2. Выбрать доступный день в календаре.
3. Выбрать свободный слот (в панели появится дата и время).
4. Нажать кнопку «Далее».
5. Повторить шаги 2–4 с другим днём и слотом.

**Ожидаемый результат:** происходит переход к шагу «Подтверждение»
(по макету — экран 05), индикатор шагов отмечает шаг 3 текущим.

**Фактический результат:** ничего не происходит — адрес страницы
не меняется, состав экрана тот же, ошибок в консоли нет. Пройти
сценарий записи до экрана «Вы записаны» невозможно ни при каком
сочетании выбранных дня и времени.

**Причина:** в разметке кнопки нет обработчика: `<button className="button button--primary" type="button">Далее</button>`.
Компонент `SummaryBar` принимает пропсы `year, month, selectedDay, selectedTime`,
но не получает колбэк перехода, а состояние активного шага в
`App.jsx` зафиксировано константой `<StepIndicator currentStep={2} />`.

**Дополнительно:** кнопка активна и при невыбранном времени
(в панели при этом написано «время не выбрано»), то есть требование
REQ-43 тоже не выполняется.

**Как чинить:** поднять шаг в состояние
(`const [step, setStep] = useState(2)`), передать в `SummaryBar` колбэк
`onNext`, заблокировать кнопку при `!selectedTime`.

**Статус:** Открыт.

## BUG-010. Календарь открывается на прошедшем месяце: «сегодня» захардкожено

| Поле | Значение |
|---|---|
| **Приоритет** | Minor |
| **Серьёзность** | Средняя (данные не соответствуют реальности) |
| **Окружение** | Chrome 157, `frontend-4-practice`, http://localhost:3000 |
| **Компонент** | API-заглушка `server/database.js`, эндпоинт `GET /api/booking/today` |
| **Требование** | REQ-16, REQ-83 |
| **Найдено** | Исследовательская сессия, 22.11.2026, 14:50 |

**Шаги воспроизведения**
1. Открыть http://localhost:3000.
2. Посмотреть, какой день выбран и какой месяц в заголовке календаря.
3. Сравнить с системной датой машины.
4. Запросить `/api/booking/today` из консоли.

**Ожидаемый результат:** выбран реальный текущий день;
заголовок календаря — текущий месяц; недоступны только даты в прошлом.

**Фактический результат:** при системной дате **22.11.2026** на экране
выбран **17 октября 2026**, в заголовке «Октябрь 2026», а API отвечает
`{"day":17,"month":9,"year":2026}`. В сетке 18 недоступных дней —
почти весь показанный месяц уже прошёл.

**Причина:** «сегодня» записано константой в `server/database.js`:
`today: { day: 17, month: 9, year: 2026 }`.

**Предлагаемое исправление:** вычислять `today` из `new Date()`
на сервере, оставив константу только для тестов — через переменную
окружения или параметр запроса.

**Влияние на тесты:** эта же константа делает невоспроизводимыми
тест-кейсы, где «сегодня» = 19.11.2026. Зависимость зафиксирована
как риск в тест-плане (задание 1, раздел 8).

**Статус:** Открыт.

## BUG-011. Сумма «К оплате» не соответствует цене выбранной услуги

|---|---|

**Шаги воспроизведения**
1. Открыть страницу выбора даты и времени.
