ТЕСТИРОВАНИЕ. ЗАДАНИЕ 3. БАГ-РЕПОРТЫ

Объект тестирования: веб-приложение онлайн-записи барбершопа «БРИТВА».

Назначение документа: регистрация дефектов, обнаруженных при выполнении чек-листа, тест-кейсов и исследовательского тестирования.

Формат баг-репорта: идентификатор, заголовок, приоритет, серьёзность, окружение, компонент, предусловия, шаги воспроизведения, ожидаемый результат, фактический результат, причина, рекомендации по исправлению, статус.

Баг-репорты BUG-001–BUG-008 относятся к ранним проверкам Frontend и Backend. BUG-009–BUG-012 обнаружены во время исследовательской сессии 22 ноября 2026 года. BUG-013 описывает альтернативный сценарий ALT-02 «Выбранное время стало занятым».

РЕЕСТР ДЕФЕКТОВ

BUG-001. При переходе на предыдущий месяц сохраняется выбранная прошедшая дата
Приоритет: Major.
Серьёзность: Средняя.
Окружение: Windows 11, Chrome 157, React-версия приложения, localhost:3102.
Компонент: календарь.
Предусловие: в календаре выбран день 25 ноября 2026 года.
Шаги воспроизведения:
1. Открыть страницу выбора даты и времени.
2. Выбрать 25 ноября 2026 года.
3. Нажать стрелку перехода к предыдущему месяцу.
4. Проверить выделенную дату.
Ожидаемый результат: после перехода в предыдущий месяц выбранная дата должна быть доступной. Если прежняя дата находится в прошлом, система выбирает ближайшую доступную дату либо снимает выбор.
Фактический результат: число 25 остаётся выбранным в прошлом месяце, а итоговая панель продолжает показывать прошедшую дату.
Причина: при переключении месяца состояние выбранного дня не проверяется на доступность.
Рекомендация по исправлению: нормализовать выбранную дату после изменения месяца и сбрасывать время, если прежний слот больше не относится к выбранной дате.
Статус: Исправлен, проверен.

BUG-002. После быстрого переключения дат отображаются слоты предыдущего дня
Приоритет: Major.
Серьёзность: Средняя.
Окружение: Windows 11, Chrome 157, frontend-4-practice, localhost:3103.
Компонент: загрузка временных интервалов.
Предусловие: сервер отвечает с задержкой, позволяющей запросам завершаться не в порядке отправки.
Шаги воспроизведения:
1. Открыть страницу выбора даты и времени.
2. Последовательно выбрать несколько разных дат с небольшими интервалами.
3. Дождаться завершения запросов.
4. Сравнить дату в заголовке блока со списком интервалов.
Ожидаемый результат: отображаются только слоты последней выбранной даты. Ответы на устаревшие запросы игнорируются.
Фактический результат: при задержке ответа мог отображаться список интервалов предыдущей даты.
Причина: ответы сервера могли поступать не в порядке отправки запросов, а клиент не проверял актуальность полученных данных.
Рекомендация по исправлению: отменять устаревшие запросы или сравнивать дату в ответе с текущей выбранной датой.
Статус: Исправлен, проверен.

BUG-003. Занятые слоты недостаточно отличаются от свободных
Приоритет: Major.
Серьёзность: Средняя.
Окружение: frontend-1-practice, браузер Chrome.
Компонент: блок временных интервалов.
Предусловие: на странице одновременно отображаются свободные и занятые слоты.
Шаги воспроизведения:
1. Открыть страницу выбора даты и времени.
2. Найти свободный и занятый интервалы.
3. Сравнить их визуальное оформление.
4. Попытаться выбрать занятый интервал.
Ожидаемый результат: занятый интервал имеет заметное визуальное отличие, зачёркнутый текст и недоступен для выбора.
Фактический результат: в первоначальной реализации занятые интервалы имели почти такое же оформление, как свободные, и отличались недостаточно заметно.
Причина: не были полноценно оформлены стили и состояние disabled.
Рекомендация по исправлению: добавить отдельный стиль занятого слота, зачёркивание текста, отключение элемента и курсор not-allowed.
Статус: Исправлен, проверен.

BUG-007. Сборка Vite завершается ошибкой из-за постороннего PostCSS-конфига
Приоритет: Blocker.
Серьёзность: Высокая.
Окружение: Windows, Node.js, Vite 8, frontend-3-practice и frontend-4-practice.
Компонент: конфигурация сборки.
Предусловие: проект находится в каталоге, для которого Vite обнаруживает внешний PostCSS-конфиг в родительской директории.
Шаги воспроизведения:
1. Перейти в каталог frontend-3-practice.
2. Установить зависимости.
3. Выполнить npm run dev или npm run build.
4. Проверить вывод терминала и браузера.
Ожидаемый результат: Vite собирает проект и запускает страницу без ошибок CSS/PostCSS.
Фактический результат: возникала ошибка Invalid PostCSS Plugin found at plugins[0], сервер возвращал 500, а страница могла отображаться пустой.
Причина: Vite подхватывал внешний конфигурационный файл PostCSS из родительской директории, который ссылался на отсутствующий плагин.
Рекомендация по исправлению: явно настроить PostCSS для проекта и исключить зависимость сборки от внешних конфигурационных файлов.
Статус: Исправлен, проверен сборкой.

BUG-008. Параллельные запросы на создание записи могут привести к гонке при проверке занятости
Приоритет: Major.
Серьёзность: Средняя.
Окружение: backend-2-practice, FastAPI, параллельные HTTP-запросы.
Компонент: POST /appointments, проверка пересечения интервалов.
Предусловие: два клиента одновременно пытаются создать запись к одному мастеру на пересекающееся время.
Шаги воспроизведения:
1. Подготовить два одинаковых запроса POST /appointments для одного мастера и пересекающихся временных интервалов.
2. Отправить запросы практически одновременно.
3. Проверить ответы API и список созданных записей.
Ожидаемый результат: только один запрос создаёт запись. Второй запрос отклоняется с HTTP 409 Conflict.
Фактический результат: в учебной реализации на хранении в памяти полноценная гарантия атомарности при конкурентном выполнении не обеспечена. Риск становится существенным при переходе на многопоточную или многопроцессную эксплуатацию и постоянную БД.
Причина: проверка конфликта и сохранение записи не объединены в атомарную операцию с блокировкой или ограничением на уровне хранилища.
Рекомендация по исправлению: выполнять проверку и создание в транзакции, а при необходимости добавлять механизм блокировки или ограничения, обеспечивающий отсутствие пересекающихся записей.
Статус: Принят как технический риск; повторное конкурентное тестирование требуется после перехода на постоянную БД.

BUG-013. Не реализована обработка ситуации, когда выбранное время стало занятым
Приоритет: Major.
Серьёзность: Высокая.
Окружение: Windows 11, Google Chrome, frontend-4-practice на http://localhost:3000, backend-2-practice на http://127.0.0.1:8000.
Компонент: подтверждение записи, обработка ответа POST /appointments.
Связанный Use Case: UC-01.
Альтернативный сценарий: ALT-02 — выбранное время стало занятым.
Связанные тест-кейсы: TC-02 из testing-2-practice.
Связанные требования: REQ-61, REQ-79.
Предусловия:
1. Frontend и Backend запущены.
2. Для мастера 1 на выбранную дату интервал 10:30 первоначально отображается свободным.
3. До подтверждения первой записи другой клиент создаёт запись на тот же интервал и к тому же мастеру.
Шаги воспроизведения:
1. Загрузить свободные интервалы для мастера 1 на тестовую дату.
2. Убедиться, что интервал 10:30 отображается свободным.
3. Создать через Backend запись мастера 1 на ту же дату и время 10:30.
4. Убедиться, что Backend вернул HTTP 201 Created для первой созданной записи.
5. Вернуться к клиентскому экрану, в котором ранее был загружен свободный интервал 10:30.
6. Попытаться оформить запись на этот же интервал через пользовательский интерфейс.
Ожидаемый результат:
1. Backend обнаруживает пересечение и возвращает HTTP 409 Conflict.
2. Повторная запись не создаётся.
3. Интерфейс сообщает, что выбранное время больше недоступно.
4. Интервал помечается как занятый.
5. Пользователь может обновить список и выбрать другое время.
Фактический результат: в текущей опубликованной реализации пользовательский путь до подтверждения записи не реализован. Кнопка «Далее» не выполняет переход, а экран подтверждения и обработчик альтернативного состояния занятого времени отсутствуют. Поэтому интерфейс не отправляет запрос и не отображает предусмотренное сообщение.
Причина: отсутствует сквозная интеграция выбора времени с подтверждением записи и обработкой HTTP 409 Conflict.
Рекомендация по исправлению: реализовать экран подтверждения, отправку POST /appointments, обработку HTTP 409, обновление слотов и действие выбора другого времени.
Статус: Открыт. API-конфликт и отсутствие соответствующего пользовательского сценария следует проверять раздельно.
