# Тестирование. Задание 1 — Виды тестирования и тест-план

**Объект тестирования:** веб-приложение «Салон БРИТВА» — путь записи клиента
(выбор услуги → выбор даты и времени → подтверждение).

## 1. Что тестируем

| Модуль | Что входит |
|---|---|
| Главная страница | шапка, навигация, блоки услуг, подвал |
| Выбор услуги | список услуг, фильтры, карточка услуги |
| Выбор даты и времени | календарь, переключение месяцев, слоты, занятые слоты |
| Подтверждение | итоговая панель, форма контактов, кнопка записи |
| API (backend) | `/api/services`, `/api/masters`, `/api/slots`, `/api/appointments` |

## 2. Виды тестирования, которые применяем

### По степени доступа к коду

- **Чёрный ящик** — основной подход: проверяем поведение через интерфейс
  и HTTP API, не зная внутренней реализации.
- **Серый ящик** — просматриваем логи сервера и структуру ответов API,
  когда нужно понять причину ошибки.

### По уровню детализации

- **Модульное** — функции вычисления свободных слотов, валидация дат,
  подсчёт стоимости.
- **Интеграционное** — связка «frontend → API → база данных».
- **Системное** — сквозной сценарий записи целиком.

### По цели

- **Функциональное** — все требования из макета и ТЗ выполняются.
- **Регрессионное** — после правок старые сценарии не сломались.
- **Smoke** — быстрая проверка «приложение вообще открывается и работает».
- **UI/визуальное** — соответствие макету: цвета, шрифты, отступы.
- **Кросс-браузерное** — Chrome, Firefox, Edge, Safari.
- **Адаптивное** — 360, 768, 1024, 1440 px.
- **Usability** — понятность шагов, читаемость, контраст.
- **Доступность (a11y)** — навигация с клавиатуры, alt-тексты, контраст.
- **Производительность** — скорость загрузки и отклика слотов.
- **Безопасность (базово)** — валидация на сервере, а не только на клиенте.

### По позитивности сценария

- **Позитивные** — корректные данные, ожидаемый успех.
- **Негативные** — неверные данные, ожидаемая ошибка с понятным сообщением.

## 3. Что НЕ входит в этот этап

- Нагрузочное тестирование с реальной нагрузкой (только имитация).
- Тестирование оплаты — оплата в приложении не реализована.
- Пентест и проверка защищённости инфраструктуры.

## 4. Окружение

| Параметр | Значение |
|---|---|
| Frontend | React 19 + Vite, http://localhost:3000 |
| Backend | FastAPI, http://127.0.0.1:8000, Swagger `/docs` |
| БД | SQLite `salon.db` |
| Браузеры | Chrome 157, Firefox, Edge |
| ОС | Windows 11 |

## 5. Тестовые данные

- Услуги: «Стрижка мужская» 1500 ₽ / 60 мин, «Маникюр» 2000 ₽ / 90 мин,
  «Бритьё» 1000 ₽ / 40 мин.
- Мастера: Алиса (стрижка, бритьё), Даниил (стрижка, борода),
  Екатерина (маникюр).
- Даты: «сегодня» = 19.11.2026, «завтра» = 20.11.2026,
  прошлое = 18.11.2026, граница месяца = 30.11 / 01.12.

## 6. Критерии начала и окончания тестирования

**Начало:** сборка разворачивается, главная страница открывается,
API отвечает на `/docs`.

**Окончание:** все тест-кейсы выполнены, критичных и блокирующих
дефектов нет, функциональность соответствует макету.

## 7. Приоритеты дефектов

| Уровень | Описание | Пример |
|---|---|---|
| Blocker | сценарий невозможен | запись не создаётся совсем |
| Critical | ключевая функция сломана | можно записаться на занятое время |
| Major | функция работает неверно | не сбрасывается время при смене дня |
| Minor | косметический дефект | неверный отступ у кнопки |
| Trivial | незаметная мелочь | опечатка в подсказке |

## 8. Риски

1. Слоты и «сегодня» захардкожены — тесты зависят от даты запуска.
2. Данные хранятся в памяти/локальной БД — после перезапуска состояние теряется.
3. Figma-макет недоступен как эталон — визуальная сверка ограничена.
