# Исследовательское тестирование

Две сессии по 35 минут без чек-листа и тест-кейсов.
Дата: 22.11.2026, 14:10–15:20.

**Окружение:** Windows 11, Chrome 157, `frontend-4-practice` на
`http://localhost:3000` (Vite 8.2.1, вместо бэкенда заглушка
`server/database.js`).
**Эталон:** макет Figma «БРИТВА — путь записи клиента» — шесть
основных экранов (Главная, Услуги, Мастер, Дата и время, Подтверждение,
Успех) и три альтернативных (ошибка телефона, слот занят, ошибка сети).

## Цель сессии

Тестирование без чек-листа и тест-кейсов: найти дефекты в местах,
где требования не сформулированы и покрытия нет.

Результат: 4 дефекта, один критичный — сквозной сценарий записи
не проходим.

---

## 1. Задачи сессий

**Первая сессия.** Переходы между шагами и состояние кнопок:
где пользователь застревает и где индикатор шагов не совпадает
с текущим состоянием. 35 минут.

**Вторая сессия.** Данные на экране: дата «сегодня», цена, адрес,
детали записи. Сверка с макетом и с реальным календарём. 35 минут.

## 2. Методика

1. Код не изменялся — только наблюдение.
2. Наблюдения фиксировались сразу, с указанием времени.
3. Данные на экране сверялись с ответом API.
4. Экран сверялся с макетом Figma.
5. Невоспроизводимые наблюдения помечались отдельно.
