USE CASE UC-01. ОФОРМЛЕНИЕ ЗАПИСИ КЛИЕНТОМ

Идентификатор: UC-01
Название: Оформление записи клиентом
Область действия: веб-приложение барбершопа «БРИТВА».
Основной участник: клиент.
Вспомогательный участник: Backend API.
Цель: оформить запись на выбранную услугу к выбранному мастеру на доступные дату и время.
Триггер: клиент нажимает кнопку «Записаться» на главной странице.

Предусловия:
1. Веб-приложение доступно.
2. Backend API доступен.
3. В системе опубликован каталог услуг.
4. В системе опубликован список мастеров.
5. Для выбранной услуги существует хотя бы один мастер.

Постусловия при успехе:
1. Запись сохранена в системе.
2. Записи присвоен уникальный идентификатор.
3. Клиент видит экран успешного оформления с деталями записи.

Основной поток:
1. Клиент открывает главную страницу.
2. Клиент выбирает действие «Записаться».
3. Система отображает каталог услуг.
4. Клиент выбирает услугу.
5. Система отображает мастеров, которые оказывают выбранную услугу.
6. Клиент выбирает мастера.
7. Система отображает календарь.
8. Клиент выбирает допустимую будущую дату.
9. Система запрашивает у Backend API свободные интервалы выбранного мастера на выбранную дату.
10. Система отображает свободные и занятые интервалы.
11. Клиент выбирает свободный интервал.
12. Система отображает итоговые сведения о выбранной услуге, мастере, дате, времени и стоимости.
13. Клиент переходит к подтверждению записи.
14. Система отображает форму подтверждения и контактные данные.
15. Клиент проверяет сведения и подтверждает запись.
16. Система проверяет заполненные данные.
17. Система отправляет Backend API запрос на создание записи.
18. Backend API повторно проверяет доступность временного интервала.
19. Backend API создаёт запись и возвращает успешный ответ.
20. Система отображает экран «Вы записаны» с деталями записи.

Альтернативный поток ALT-01. Некорректный номер телефона:
1. На шаге 15 клиент вводит номер телефона в неправильном формате.
2. Система проверяет формат номера.
3. Система выделяет поле и отображает сообщение об ошибке.
4. Запрос на создание записи не отправляется.
5. Клиент исправляет номер и повторяет подтверждение.

Альтернативный поток ALT-02. Выбранное время стало занятым:
1. На шаге 11 клиент выбирает интервал, который на момент загрузки был свободен.
2. До подтверждения другой клиент создаёт запись на тот же интервал для того же мастера.
3. Первый клиент подтверждает свою запись.
4. Backend API обнаруживает пересечение записей и возвращает HTTP 409 Conflict.
5. Система сообщает, что выбранное время больше недоступно.
6. Система обновляет список временных интервалов и помечает занятый интервал как недоступный.
7. Система предоставляет действие «Выбрать другое время».
8. Клиент выбирает другой доступный интервал.

Альтернативный поток ALT-03. Ошибка сети:
1. На шаге 17 возникает ошибка сетевого соединения.
2. Система сообщает, что запись не отправлена.
3. Система предоставляет возможность повторить отправку запроса.
4. Перед повторной отправкой система проверяет результат предыдущей операции, чтобы не создать дублирующую запись.
5. После восстановления соединения клиент повторяет действие.

Исключения:
1. Если каталог услуг недоступен, система отображает сообщение об ошибке и предлагает повторить загрузку.
2. Если выбранный мастер не оказывает выбранную услугу, система не позволяет продолжить оформление.
3. Если выбранная дата находится в прошлом, система запрещает её выбор.
4. Если выбранный временной интервал не помещается в рабочий график, Backend API отклоняет запрос.
5. Если обязательные данные отсутствуют или имеют неправильный формат, Backend API возвращает ошибку валидации.

Бизнес-правила:
1. Мастер может выполнять только услуги, указанные в его списке специализаций.
2. Запись разрешена только на будущую дату и время.
3. Время начала и окончания услуги должно полностью находиться в пределах рабочего графика.
4. У одного мастера не может быть двух пересекающихся записей.
5. Проверка доступности выполняется повторно при создании записи, даже если слот ранее отображался свободным.
6. При конфликте временных интервалов Backend API возвращает HTTP 409 Conflict.

Связанные требования:
REQ-60 — создание записи.
REQ-61 — проверка пересечения записей.
REQ-69–REQ-77 — экраны и этапы основного сценария.
REQ-78 — проверка номера телефона.
REQ-79 — обработка занятого временного интервала.
REQ-80 — обработка сетевой ошибки.

Связанные проверки:
TC-01 — успешное оформление записи.
TC-02 — выбранное время стало занятым до подтверждения.
BUG-013 — отсутствие обработки конфликта занятого времени в пользовательском интерфейсе.
