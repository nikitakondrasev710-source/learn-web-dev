3. ТЕСТ-КЕЙСЫ ПО СЦЕНАРИЯМ ЗАДАНИЯ

TC-01. Успешное оформление записи клиентом

Идентификатор: TC-01
Название: Успешное оформление записи клиентом
Сценарий: основной поток UC-01
Связанные требования: REQ-60, REQ-69, REQ-70, REQ-71, REQ-72, REQ-73, REQ-75, REQ-76, REQ-77
Приоритет: высокий
Тип проверки: позитивное, функциональное, сквозное

Предусловия:
1. Frontend и Backend запущены.
2. Каталог услуг и список мастеров доступны.
3. Выбранный мастер оказывает выбранную услугу.
4. На выбранную дату у мастера есть свободный временной интервал.
5. В системе отсутствует запись, пересекающаяся с выбранным интервалом.

Тестовые данные:
Клиент: Никита.
Услуга: доступная услуга из каталога.
Мастер: мастер, оказывающий выбранную услугу.
Дата: ближайшая допустимая будущая дата.
Время: 12:00, если этот интервал свободен.
Комментарий: тестовая запись.

Шаги выполнения:
1. Открыть главную страницу приложения.
2. Нажать кнопку «Записаться».
3. Выбрать услугу из каталога.
4. Перейти к выбору мастера.
5. Выбрать мастера, который оказывает выбранную услугу.
6. Перейти к календарю.
7. Выбрать допустимую будущую дату.
8. Выбрать свободный временной интервал.
9. Перейти к экрану подтверждения.
10. Проверить сведения об услуге, мастере, дате, времени и стоимости.
11. Подтвердить запись.

Ожидаемый результат:
1. После выбора услуги, мастера, даты и времени пользователь последовательно переходит между этапами записи.
2. На экране подтверждения отображаются корректные сведения о записи.
3. Сервер принимает запрос на создание записи и возвращает HTTP 201 Created.
4. В системе появляется ровно одна новая запись.
5. Пользователь видит экран «Вы записаны» с деталями созданной записи.

Фактический результат:
Полный сценарий в текущей реализации не проходит. Главная страница, отдельный экран выбора мастера и экран успешной записи отсутствуют. На странице выбора даты и времени кнопка «Далее» не выполняет переход к подтверждению.

Статус: не пройден.
Связанный дефект: BUG-012. Отдельная проблема перехода по кнопке «Далее» описана в BUG-009.

TC-02. Выбранное время стало занятым до подтверждения записи

Идентификатор: TC-02
Название: Обработка ситуации, когда выбранный временной интервал занял другой клиент
Сценарий: альтернативный поток ALT-02 из UC-01
Связанные требования: REQ-61, REQ-79
Приоритет: критический
Тип проверки: негативное, функциональное, интеграционное

Предусловия:
1. Frontend и Backend запущены.
2. Клиент открыл страницу выбора даты и времени.
3. Для выбранного мастера и даты временной интервал 10:30 первоначально отображается свободным.
4. До отправки подтверждения другой клиент создаёт запись на тот же временной интервал для того же мастера.

Тестовые данные для Backend:
Клиент: Никита.
Идентификатор мастера: 1.
Идентификатор услуги: 1.
Дата и время начала: 2026-12-10T10:30:00.
Продолжительность услуги: 60 минут согласно каталогу Backend.
Комментарий: проверка конфликта временных интервалов.

Шаги выполнения:
1. Загрузить свободные интервалы для мастера 1 на 10 декабря 2026 года и убедиться, что 10:30 отображается свободным.
2. До подтверждения записи создать через Backend другую запись для мастера 1 с началом 10 декабря 2026 года в 10:30.
3. Убедиться, что Backend создал вторую запись и вернул HTTP 201 Created.
4. Вернуться к первоначально открытой странице клиента, на которой интервал 10:30 ещё отображается свободным.
5. Выбрать интервал 10:30 и перейти к подтверждению записи.
6. Отправить запрос на создание записи с тем же мастером, датой и временем.
7. Проверить ответ Backend и реакцию пользовательского интерфейса.

Ожидаемый результат:
1. Backend обнаруживает пересечение временных интервалов и возвращает HTTP 409 Conflict.
2. Повторная запись не создаётся.
3. Интерфейс сообщает, что выбранное время уже занято.
4. Занятый временной интервал помечается как недоступный.
5. Пользователю доступно действие «Выбрать другое время».
6. После обновления списка отображаются актуальные свободные интервалы.

Фактический результат:
Backend должен отклонить пересекающуюся запись с HTTP 409 Conflict. В пользовательском интерфейсе сценарий не может быть завершён: переход к подтверждению не реализован, запрос на создание записи из интерфейса не отправляется, экран обработки занятого времени отсутствует.

Статус: не пройден на уровне пользовательского интерфейса. Проверка ответа Backend выполняется отдельно.
Связанный дефект: BUG-013. Общая проблема отсутствующих экранов также указана в BUG-012.
